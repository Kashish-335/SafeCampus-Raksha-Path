# SafeCampus (Raksha Path) — Database Schema & Security Policies

SafeCampus utilizes Supabase (PostgreSQL 15+) with Row Level Security (RLS) enabled on all tables. It also includes an offline-first storage adapter with full schema parity in IndexedDB / LocalStorage.

---

## 1. Tables & Entity Definitions

### `public.reports`
Primary table storing student incident reports, infrastructure hazards, and harassment complaints.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | Primary Key, `DEFAULT gen_random_uuid()` | Unique report identifier |
| `title` | `TEXT` | `NOT NULL` | Short summary of the hazard |
| `description` | `TEXT` | `NOT NULL` | In-depth student description |
| `category` | `report_category_enum` | `NOT NULL` | Harassment, Broken Light, CCTV, Ragging, etc. |
| `urgency` | `INTEGER` | `CHECK (urgency BETWEEN 1 AND 5)` | Severity score (5 = imminent threat) |
| `latitude` | `DOUBLE PRECISION` | `NOT NULL` | Geolocation latitude coordinate |
| `longitude` | `DOUBLE PRECISION` | `NOT NULL` | Geolocation longitude coordinate |
| `location_name` | `TEXT` | `NOT NULL` | Named campus landmark or descriptive spot |
| `photo_url` | `TEXT` | Nullable | Encrypted image attachment |
| `is_anonymous` | `BOOLEAN` | `DEFAULT TRUE` | Anonymity protection flag |
| `user_id` | `UUID` | References `profiles(id)` | Author reference (NULL if anonymous) |
| `status` | `report_status_enum` | `DEFAULT 'submitted'` | Lifecycle: `submitted`, `assigned`, `in_progress`, `resolved` |
| `ai_summary` | `TEXT` | Nullable | 1-line executive synopsis generated by Gemini |
| `is_duplicate` | `BOOLEAN` | `DEFAULT FALSE` | Duplicate hazard indicator |
| `duplicate_of` | `UUID` | References `reports(id)` | Parent report link if duplicate |
| `assigned_to` | `TEXT` | Nullable | Department / warden responsible |
| `created_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Submission timestamp |
| `resolved_at` | `TIMESTAMPTZ` | Nullable | Verification timestamp upon resolution |

### `public.sos_alerts`
High-priority emergency alerts generated by Silent SOS or Walk With Me route deviations.

| Column | Type | Constraints | Description |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | Primary Key | Unique SOS distress event ID |
| `user_id` | `UUID` | References `profiles(id)` | User triggering alert |
| `latitude` | `DOUBLE PRECISION` | `NOT NULL` | Current incident latitude |
| `longitude` | `DOUBLE PRECISION` | `NOT NULL` | Current incident longitude |
| `location_name` | `TEXT` | Nullable | Reverse-geocoded or estimated spot |
| `trigger_type` | `TEXT` | `NOT NULL` | `button_press`, `shake`, `volume_sim`, `code_word`, `walk_deviation` |
| `status` | `TEXT` | `DEFAULT 'active'` | `active`, `acknowledged`, `resolved`, `false_alarm` |
| `contacts_notified`| `JSONB` | `DEFAULT '[]'::jsonb` | List of notified phone numbers & channels |
| `dispatched_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Timestamp of dispatch |

---

### `public.safety_checkpoints`
Campus security infrastructure and emergency points of contact.

| Column | Type | Description |
| :--- | :--- | :--- |
| `id` | `UUID` | Primary Key |
| `name` | `TEXT` | e.g. "Girls Hostel Guard Booth & Women Helpdesk" |
| `type` | `TEXT` | `security_post`, `emergency_callbox`, `well_lit_zone`, `medical_post`, `women_helpdesk` |
| `latitude` | `DOUBLE PRECISION` | Station latitude |
| `longitude` | `DOUBLE PRECISION` | Station longitude |
| `phone` | `TEXT` | Direct intercom / hotline number |
| `is_active` | `BOOLEAN` | Station operational status |

## 2. Row Level Security (RLS) Policy Architecture

All tables strictly enforce zero-trust policies:

```sql
-- 1. Anyone can submit an anonymous report without needing prior authentication
CREATE POLICY "Anyone can insert reports" ON public.reports
  FOR INSERT WITH CHECK (true);

-- 2. Public read for map pins to populate transparent heatmaps
CREATE POLICY "Public read for reports map" ON public.reports
  FOR SELECT USING (true);

-- 3. Only verified Staff & Admins can update ticket assignment and status
CREATE POLICY "Admins can update reports" ON public.reports
  FOR UPDATE USING (
    EXISTS (
      SELECT 1 FROM public.profiles
      WHERE profiles.id = auth.uid() AND profiles.role IN ('admin', 'warden', 'security_lead', 'icc_member')
    )
  );

-- 4. Emergency SOS triggers can be written by any user in distress
CREATE POLICY "Anyone can trigger SOS" ON public.sos_alerts
  FOR INSERT WITH CHECK (true);
```
